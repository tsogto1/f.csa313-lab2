## SLO ба тайлбар

Алхам 2-т 5 VU-ын тестээр хэмжсэн p95 = 346.06 ms. Эндээс SLO-г p95 < 520 ms, error rate < 1% гэж сонгов. Энэ утга нь baseline p95-ийг 1.5 дахин нэмснээр боломжийн тайван хязгаарыг гаргасан тул latency-ийг муутгахаас өмнө амжилттай биелдэг. Нийтээр хэлбэл, 5 VU-ын үндсэн benchmark-ээс 50% хэтрүүлсэн хоёр нийтлэг хязгаартай SLO байна. Threshold нь ангиллын эхний пүрвэшийг тогтвортой барьж, доод хязгаарыг хэтрүүлсэн тестийг автоматаар FAIL болгоно.

## Дүгнэлт (8-10 өгүүлбэр)

Эхний 5 VU гүйцэтгэл илүү удааширсан боловч latency графикт тогтворжсон байсан. 30 VU-д throughput 6.7 req/s-ээс 40.8 req/s руу өсч, нэгж хэрэглэгчийн хариу хугацааг тогтвортой болгосон. 100 VU-д throughput 134.95 req/s хүртэл өсөөд p95 338.44 ms хэвээрээ байсан. Error rate 0% хэвээр үлдэж, k6-ийн checksum/validation шалгуур бүтцэд асуудал гараагүй. Энэ нь load test-д throughput болон latency олон хамааралтай болохыг баталж байна. Лекц 2-т үзсэн latency p95/p99, throughput, error rate, availability гэсэн ойлголтууд энэ хэмжилтээр харьцангуй нотлогдсон. Үйлчлүүлэгчийн туршлага нь VU-уудын тоо өсөхөд шууд муудаж, хамгийн ихдээ p95-ийг нэмэгдүүлж болно. SLO-гийн шалгуур p95 < 520 ms болон error rate < 1% нь бидний 5 VU baseline-д тулгуурласан. Бид 5 VU-ын 346 ms p95-ээс 1.5 дахин өндөр хязгаартай тохируулалтаар SLO-г томруулаагүй. Эцэст нь, k6-ийг RUN хийхэд өгсөн текст тайлан нь load test-ийн бодит хариуг баталгаажуулсан.
